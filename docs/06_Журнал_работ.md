### 2. Распознавание и виртуальный стенд

Модели распознавания не было; камеры и макета пока нет, поэтому сделан виртуальный стенд,
который рисует кадры так, как их увидит выбранная камера. Подробно — [05_Виртуальный_стенд.md](05_Виртуальный_стенд.md).

- `cv/camera_model.py` — модель камеры (матрица K + поза по меткам через `solvePnP`), проекция
  пикселя на плоскость любой высоты.
- `cv/sim/` — описание стенда (`stands/maquette_a.json`), генератор сцен, рендер кадров IMX183 + 12 мм
  (20 Мп, свет, тени, шум, расфокус, помехи, рука человека), генератор датасета YOLO, испытание, демо.
- `cv/detector.py`, `cv/tiling.py` — детектор YOLO с масштабированием и тайлингом.
- `cv/pipeline.py` — конвейер кадра: качество → детекция → отсев кадров с человеком → координаты → ячейка;
  геопривязка с учётом высоты полок (`SurfaceAwareMapper`).
- `cv/training/train.py` — обучение YOLO (аугментации для монохрома, продолжение после сбоя).
- Обучена модель `sklad-sim-v1` (YOLO11s, 500 синтетических кадров, 50 эпох, RTX 3080).

Результаты на 40 тестовых кадрах (своя установка камеры, модель их не видела):

### 4. Исправления по итогам испытаний

- Контроль качества бракует резкие кадры при тусклом свете: дисперсия лапласиана зависит от
  контраста. Перешли на нормированную резкость `var(Laplacian) / var(image) × 1000`, порог 20.
- Обучение на Windows падало по памяти: `batch 4`, `workers 2`, без кэша в RAM, флаг `--resume`.
- `scripts/seed_demo.py` берёт геометрию макета из описания стенда (одно место вместо двух копий),
  флаг `--replace` пересоздаёт демо-склады.

### Решения, которые нужно внести в ТЗ

1. ФТ-ЛОК-02, ФТ-КАМ-05: геопривязка через модель камеры (K + поза) с учётом высоты поверхности;
   в `camera_calibrations` добавить `rvec`, `tvec`, у ячеек — высоту поверхности.
2. ФТ-СКН-06: резкость — нормированная, а не абсолютная дисперсия лапласиана.
3. Камера над макетом — на 1,2 м (а не 1,0 м), стеллажи не ближе 8 см к краю стола.
4. При сопоставлении сканов не считать пропавшими объекты под рамкой человека.
