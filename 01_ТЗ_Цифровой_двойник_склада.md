### 1.3. Термины и сокращения

| Термин | Определение |
|---|---|
| Цифровой двойник (ЦД) | Программно-информационная модель склада, отражающая структуру помещения, объекты хранения, их положение и историю изменений на основе данных сканирования |
| Сканирование | Однократный сеанс получения изображения (или набора кадров) из источника с последующим распознаванием |
| Детекция | Результат обнаружения одного объекта на одном изображении: класс, рамка (bbox), уверенность |
| Объект учёта | Сущность в БД, соответствующая физическому объекту (коробка, паллета, контейнер), существующая между сканированиями |
| Сопоставление (matching) | Процедура связывания детекции текущего сканирования с объектом учёта из предыдущего состояния |
| Гомография | Проективное преобразование координат изображения (пиксели) в координаты плоскости плана склада (метры) |
| Ячейка | Минимальная адресуемая единица хранения (место на ярусе стеллажа или участок напольной зоны) |
| Занятость | Отношение числа занятых ячеек к общему числу ячеек зоны/стеллажа |
| CV | Computer Vision — компьютерное зрение |
| mAP@0.5 | Средняя точность детектора при пороге IoU = 0,5 |
| IoU | Intersection over Union — мера перекрытия рамок |
| WMS/ERP | Системы управления складом / предприятием |
| ROI | Region of Interest — область интереса на кадре |

## 2. Назначение и цели создания Системы

### 2.1. Назначение

Система предназначена для автоматизированного контроля состояния склада путём:

- получения изображений складских зон с камер или из файлов;
- обнаружения и классификации складских объектов методами CV;
- определения положения объектов в координатах склада и привязки к зонам, стеллажам и ячейкам;
- ведения цифровой модели склада и истории её изменений;
- визуализации, поиска и формирования отчётов.

Система **контролирует и отображает** состояние склада, но **не управляет** физическими процессами.

### 2.2. Цели

| № | Цель | Измеримый показатель |
|---|---|---|
| Ц1 | Сократить время на визуальную инвентаризацию демо-зоны | Время получения актуального состояния зоны ≤ 1 мин против ручного обхода |
| Ц2 | Обеспечить автоматическое обнаружение изменений | Обнаружение появления/исчезновения объекта в зоне обзора при повторном сканировании (recall ≥ 0,9 на тестовом наборе) |
| Ц3 | Дать наглядное представление заполненности | 2D-план с окраской ячеек по занятости, обновление после каждого сканирования |
| Ц4 | Обеспечить прослеживаемость | История событий по каждому объекту учёта с привязкой к сканированию и исходному изображению |

### 2.3. Задачи

1. Разработать модель данных склада (склад → зоны → стеллажи → ярусы → ячейки).
2. Разработать базу данных объектов, сканирований, детекций и событий.
3. Реализовать приём изображений: загрузка фото/видео, захват с промышленной камеры.
4. Реализовать детекцию и классификацию объектов.
5. Реализовать калибровку камеры и пересчёт координат в систему координат склада.
6. Реализовать привязку объектов к зонам и ячейкам.
7. Реализовать сопоставление объектов между сканированиями и генерацию событий.
8. Реализовать веб-интерфейс с 2D-планом склада.
9. Реализовать поиск, фильтрацию, историю и отчёты.
10. Обеспечить расширяемость под дополнительные камеры и источники.

## 3. Характеристика объекта автоматизации

### 3.1. Объект автоматизации

Складское помещение (или его демонстрационная модель) со стеллажным и напольным хранением. Для прототипа принимаются два варианта испытательного стенда:

| Вариант | Описание | Рабочая дистанция камеры | Поле зрения камеры |
|---|---|---|---|
| **А. Настольный макет** (основной) | Макет склада масштаба ~1:10 на столе 1,2 × 0,8 м: 2 зоны, 4–6 стеллажей, модели коробок, паллет, контейнеров | ~1,0 м, вид сверху | ≈ 1,1 × 0,73 м |
| **Б. Демо-зона реального помещения** (дополнительный) | Участок помещения 5 × 4 м с 1–2 стеллажами | 4–6 м, камера под потолком или на штативе | ≈ 4,4–6,6 × 2,9–4,4 м |

Полный склад (пример: 30 × 15 × 6 м, 20 стеллажей, 4 зоны) моделируется в Системе как структура данных; распознаванием покрывается только зона обзора имеющейся камеры.

### 3.2. Типы складских объектов (справочник по умолчанию)

| Код | Класс | Обязателен для распознавания | Примечание |
|---|---|---|---|
| `box` | Коробка | Да | Основной класс |
| `pallet` | Паллета (пустая или с грузом) | Да | |
| `container` | Контейнер / ящик пластиковый | Да | |
| `person` | Человек | Да | Используется для отбраковки кадров и безопасности, не является объектом учёта |
| `forklift` | Погрузочная техника | Нет (желательно) | Не является объектом учёта |
| `rack` | Стеллаж | Нет | Стеллажи задаются вручную в структуре склада, детекция — только для проверки |

Справочник расширяется администратором (добавление класса требует дообучения модели).

### 3.3. Пользователи

| Роль | Права |
|---|---|
| **Администратор** | Управление пользователями и ролями; конфигурация Системы; управление камерами и их калибровкой; редактирование структуры склада; управление справочником типов; управление версиями модели CV; все права оператора |
| **Оператор склада** | Просмотр ЦД; запуск сканирования; просмотр объектов и детекций; ручное подтверждение/исправление результата распознавания; поиск; история; отчёты |
| **Наблюдатель** (опционально) | Только просмотр ЦД и отчётов |

#### 4.1.3. Режимы функционирования

| Режим | Описание |
|---|---|
| Ручное сканирование | Оператор нажимает «Сканировать» для выбранной камеры/зоны или загружает файл |
| Плановое сканирование | Захват по расписанию (интервал задаётся администратором, по умолчанию 5 мин; может быть отключено) |
| Обработка видео | Из видеозаписи извлекаются кадры с заданным шагом (по умолчанию 1 кадр / 2 с), каждый обрабатывается как отдельное сканирование либо агрегируется в одно |
| Сервисный | Калибровка камеры, настройка ROI, проверка модели; распознавание в ЦД не записывается |
| Аварийный | Источник недоступен — Система работает с последним известным состоянием, помечая данные как устаревшие |

- Пароли хранятся в виде хеша (bcrypt/argon2) (НФТ-Б-01).

#### 4.4.5. Алгоритмическое обеспечение

**Конвейер обработки одного сканирования:**

1. Получение кадра (Mono8 5472 × 3648 или файл) и метаданных.
2. Контроль качества: средняя яркость в диапазоне, доля пересвеченных пикселей < 5 %, дисперсия лапласиана > порога.
3. Устранение дисторсии (если есть калибровка), обрезка по ROI камеры.
4. Преобразование Mono → 3 канала.
5. Детекция: тайлы 1280 × 1280 с перекрытием 20 % → YOLO → объединение (NMS) либо вход модели ≥ 1280 при биннинге 2×2.
6. Фильтрация по порогу уверенности и по ROI; отбраковка кадра при наличии людей/техники в ROI.
7. (Опц.) Чтение штрихкодов в пределах bbox.
8. Расчёт опорной точки → гомография → (x, y) м → поиск зоны/стеллажа/ячейки.
9. Сопоставление с активными объектами в зонах обзора камеры (п. ФТ-ЦД-02).
10. Генерация событий, обновление объектов, занятости, снимка состояния — в одной транзакции.
11. Сохранение изображения с разметкой, уведомление интерфейса.

**Правила сопоставления:**

```
для каждой камеры C и сканирования S:
  A = активные объекты, чья ячейка входит в зоны обзора C
  D = детекции S класса is_tracked с уверенностью ≥ порога
  1) пары по совпадающему штрихкоду → confirmed / moved
  2) для остальных: матрица стоимости = расстояние(x,y), ∞ при разных классах
     или расстоянии > порога; венгерский алгоритм → confirmed
  3) несопоставленные детекции → новые объекты (appeared)
  4) несопоставленные объекты → missed_scans += 1;
     при missed_scans ≥ N → status = missing, событие disappeared
  5) если в одном сканировании есть disappeared и appeared одного класса
     без штрихкода → дополнительно событие moved с is_assumed = true
```

## 7. Требования к подготовке объекта к вводу Системы в действие

1. Определить структуру склада, измерить помещение, составить план с размерами.
2. Внести в Систему склад, зоны, стеллажи; сгенерировать ячейки.
3. Смонтировать камеру на жёстком креплении, установить освещение.
4. Настроить фокус и диафрагму (f/4–f/5.6), зафиксировать стопорными винтами; установить ручную экспозицию.
5. Выполнить калибровку внутренних параметров (шахматная доска) и гомографии (опорные точки, отмеченные на полу/макете).
6. Настроить ROI и зоны обзора камеры.
7. Зарегистрировать пользователей.
8. Заполнить справочник типов объектов, при наличии — справочник товаров со штрихкодами.
9. Загрузить и активировать обученную модель.
10. Выполнить тестовое сканирование эталонной расстановки и сверить результат.
11. Настроить расписание сканирования и резервное копирование.

При изменении положения камеры калибровка гомографии выполняется повторно.

## 9. Границы объёма работ

### 9.1. Входит в проект

- цифровая модель склада (2D) со структурой зон, стеллажей, ячеек;
- база данных и API;
- загрузка изображений и видео, захват с одной промышленной камеры USB3;
- обучение/дообучение детектора на собственном датасете;
- распознавание обязательных классов (коробка, паллета, контейнер, человек);
- калибровка камеры и пересчёт координат в систему склада;
- привязка объектов к зонам и ячейкам;
- сопоставление между сканированиями, история изменений;
- визуализация, поиск, отчёты;
- испытания на стенде (макет и/или демо-зона).

### 9.2. Не входит в проект

- управление роботами, погрузчиками, автоматическое управление складом;
- физическое перемещение товаров;
- полноценная WMS/ERP, интеграция с внешними WMS/ERP (предусматривается только REST API и экспорт);
- автоматическое оформление документов;
- высокоточная 3D-навигация и определение яруса по одному виду сверху;
- видеоаналитика в реальном времени (трекинг движущихся объектов);
- покрытие камерами всего склада и работа с большим числом камер;
- распознавание конкретного товара по внешнему виду (SKU) без штрихкода;
- распознавание по цвету (камеры монохромные);
- эксплуатация в неотапливаемых, пыльных, влажных помещениях (камеры IP30).

### 9.3. Перспективы развития

3D-модель; несколько камер со сшивкой зон обзора; IP-камеры (RTSP) и GigE-версии камер; трекинг в реальном времени; RFID; интеграция с 1С/WMS; мобильное приложение; определение объёма заполнения по стереопаре/глубинной камере.
