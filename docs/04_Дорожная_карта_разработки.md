Рабочий трекер по модулям кода. Календарь и контрольные точки — в [плане реализации](02_План_реализации.md);
здесь — что уже сделано в репозитории и в каком порядке идти дальше. Порядок изменён относительно
календаря: программная часть, не требующая стенда, ведётся параллельно со сборкой макета и съёмкой
датасета, чтобы к моменту готовности модели CV конвейер уже был.

## Выводы виртуального стенда, которые меняют план

- Геопривязка через одну гомографию пола даёт 82 % верных ячеек (нужно ≥ 90 %); с моделью камеры
  и высотами полок — 100 %. Нужны поля позы в `camera_calibrations` и `surface_z` для ячеек.
- Камеру над макетом ставить на 1,2 м, а не 1,0 м.
- При сопоставлении не считать пропавшими объекты под рамкой человека.

## Известные упрощения текущей версии

- Занятость в KPI считается по всем ячейкам, хотя при виде сверху нижние ярусы не наблюдаются;
  при реализации `occupancy.py` ввести состояние «неизвестно» для невидимых ярусов (ФТ-ЦД-05).
- Тесты API работают на SQLite; поведение, специфичное для PostgreSQL, проверяет CI (`alembic check`).
